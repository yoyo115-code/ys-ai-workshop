# v0.3.0 Draft — Resume Optimizer & Versioning

状态：功能分支已实现，尚未合并或发布 tag。

## 已实现范围

- 从用户已保存的 Career Match 申请建立 Resume 和初始文本版本。
- 生成带原句、建议句、原因、JD/简历证据和事实风险的逐条建议。
- 接受、拒绝、手工编辑、单条重新生成、最近操作 Undo 和刷新/重新登录后继续。
- 将已接受/编辑的建议事务化生成新文本快照，并查看历史、Diff 和恢复。
- 响应式工作区，含 Loading、Empty、Error、Retry、风险筛选、保存状态和未保存离开确认。

## API

新增 10 个 Resume Optimizer/Version API：建议生成与列表、决策、重新生成、Undo、版本创建、历史、详情、比较与恢复。完整路径与错误语义见 `docs/API.md`。Career Match 和五个 AI Labs 路径未变。

## 数据库变化

`database/migrations/0002_resume_versioning.sql` 新增：

- `resumes`
- `resume_versions`
- `resume_suggestions`
- `resume_suggestion_events`

ResumeVersion 是不可变完整文本快照。创建与恢复只追加新版本，不原地覆盖历史。版本生成用单个 SQLite 事务保证失败时完整回滚。

## Prompt 与防编造

`resume_suggestion_v1` 把简历、JD 和匹配内容标记为不可执行的待分析数据，禁止编造数字、技能、职责、公司、时间和成果。模型输出先通过禁止额外字段的 Pydantic Schema，再由确定性代码定位原句和双向证据，标记新事实风险并阻止高风险直接接受。

## 测试结果

53 项自动化测试在 mock Provider 和临时 SQLite 下通过，覆盖证据/风险、状态机、幂等、重生成保留旧记录、事务回滚、数据隔离、版本操作、前端交互契约、Career Match 和五个 AI Labs 回归。测试不调用真实模型。

## 当前限制

- 版本是结构化纯文本，不保留原始 PDF/DOCX 排版，不支持保真导出。
- 重复原句会因替换歧义阻止版本生成。
- 风险检测是保守启发式，可能误报，用户必须复核事实。
- 同步模型调用和 SQLite 尚不适合大规模并发部署。
- Cover Letter、面试准备、分享链接、OCR 和新 AI Labs 未实现。

## 后续计划

先对 v0.3 执行真实浏览器验收与个人数据保留策略，再独立评估 PDF/DOCX 版式导出和 Cover Letter；本分支不包含这些功能。
