# Y's AI Workshop v0.2.0

发布日期：2026-07-30

## 功能范围

v0.2.0 发布 Career Match MVP，实现“简历 + 岗位 JD → 可保存、可解释的岗位匹配分析”闭环：

- 用户可粘贴简历文本，或上传 PDF/DOCX 简历。
- 用户可保存公司、岗位、地点、语言与完整 JD。
- 系统按总体结论、已覆盖、部分覆盖、缺失、信息不足、表达问题、岗位风险和分析限制展示结果。
- 每条匹配项包含 JD 原文、简历证据、解释与证据充分程度，不提供无评测依据的百分比或录用概率。
- 申请按用户保存，支持刷新或重新登录后打开、显式重试和删除。
- 原有 Resume Optimizer、Copywriting、Translation、PDF Summary 与 CSV Analysis 继续保留在 AI Labs，接口路径不变。

本版本不包含逐条简历改写、Cover Letter、面试模拟、分享链接、CSV Agent 或新管理后台。

## API

新增需要 Session 的 Career API：

- `POST /career/applications`：解析并保存简历与岗位信息。
- `GET /career/applications`：列出当前用户最近的申请。
- `GET /career/applications/{application_id}`：读取当前用户自己的申请和最近成功分析。
- `POST /career/applications/{application_id}/analyze`：生成分析；`retry: true` 时显式重新分析。
- `DELETE /career/applications/{application_id}`：删除当前用户自己的申请及关联数据。

模型未配置、超时、Provider 失败、非法 JSON 和证据不满足原文约束时，API 返回明确错误。创建申请和模型分析相互分离，因此模型失败不会丢失已经保存的简历与 JD。

## 数据库变化

新增 migration：`database/migrations/0001_career_match.sql`。

新增表：

- `job_applications`：用户、岗位元数据、JD、语言和流程状态。
- `resume_sources`：来源类型、文件名、提取文本、内容哈希和解析状态；不保存上传原文件。
- `match_analyses`：总体结论、摘要、限制、Provider、模型、Prompt 版本、状态和错误码。
- `match_items`：匹配类别、JD 原文、简历证据、解释、证据充分程度和排序。

外键负责关联数据级联删除；部分唯一索引限制同一申请最多存在一个 `analyzing` 分析记录。

## Prompt 与安全约束

Career Match 使用版本化 Prompt `career_match_v1` 和 DeepSeek `deepseek-chat`。简历与 JD 被标记为不可信待分析数据，其中包含的指令不会作为系统指令执行。

模型不得编造技能、数字、成绩、职责、学历或经历；无证据时必须返回 missing、uncertain 或 unknown 含义。Provider 输出先经过 Pydantic Schema 校验，再验证 JD 与简历引用来自输入原文。Career Match 活动日志只保存申请 ID、状态、耗时和技术元数据，不保存完整简历、JD 或模型响应。

## 已知限制

- PDF 不支持 OCR，扫描版 PDF 无法提取简历文字。
- DOCX 仅读取主文档段落，复杂文本框、图片和附件可能无法提取。
- Career Match 第一版固定使用单一 DeepSeek Provider，不进行双模型比较。
- 原文引用校验能够降低编造，但语义判断仍需用户复核。
- 当前使用同步请求、SQLite 与 Header Session，尚未针对生产级并发部署设计。
- 尚无浏览器自动化测试。
